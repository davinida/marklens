# MarkLens X1 호칭(발음) 유사도 설계

- 기준일: 2026-09-17 (v1 초판 → v1.1 검토 반영 → v1.2 마무리) · 구현: `ml/src/axes/x1_phonetic.py`, `ml/src/axes/korean_brands.py` · 테스트: `ml/tests/test_axes.py` · 보고: `ml/scripts/x1_report.py` · 로마자 후보 캐기: `ml/scripts/x1_mine_romanization.py`
- 규약(공통-2): `phonetic_similarity(name_a, name_b, *, extra_generic=frozenset()) -> float` 0.0~1.0(높을수록 유사), 순수 함수, 표준 라이브러리만 사용. 외부 G2P 라이브러리는 검증 후 **채택하지 않았다**(§7).

## 1. 판례 ↔ 구현 매핑

| 판례 규칙 | 구현 | 위치 |
|---|---|---|
| ① 호칭이 가장 중요 | 통합 모델의 중심 축(X1 내부와 무관, 가중치 해석 시 참고) | 모듈 docstring |
| ② 짧은 상표는 첫음절 강세 | 음절 위치별 비용 가중치. "첫음절 2배" 기준선을 음절 수별로 세분화(§2) | `POSITION_WEIGHTS`, `_position_weights` |
| ③ 여러 호칭 중 하나만 유사해도 유사 | 상표명 하나 → 발음 후보 여러 개 → 모든 쌍의 **최댓값** | `pronunciation_candidates`, `phonetic_similarity` |
| ④ 외국어는 자연스러운 국내 발음 | 영문 토큰 → 한글 발음(국내 브랜드·지명 로마자 표 → 예외 사전 → 외래어 표기법 근사 룰, 모두 토큰 완전일치). 3자 이하·모음 없는 토큰은 낱자 읽기 추가 | `_g2p_word`, `KOREAN_BRAND_ROMANIZATION`, `KOREAN_PLACE_ROMANIZATION`, `_g2p_rule`, `LETTER_READINGS` |
| ⑤ 한영 병기 시 한글 우선 | 영문 읽기가 한글과 `PAIRED_THRESHOLD`(0.8) 이상이면 병기 → 영문 읽기 폐기. 토큰 단위 + 구 단위(제거 전·후 어느 쪽이든) | `_apply_paired_rule` |
| 분리관찰 | 제거 후 각 토큰의 2음절 이상 읽기를 독립 후보로. **알파벳·숫자 1글자 토큰에서 나온 읽기(K→케이, 7→세븐)는 제외** | `_candidates_cached` (c) |
| 불가분 결합 예외 | 제거 전 토큰 전체 결합음을 항상 후보에 유지(1글자 토큰 읽기도 여기에는 포함) | `_candidates_cached` (a) |
| 요부관찰 | 회사 형태·부가어·기능어 제거(`UNIVERSAL_GENERIC`) + 호출자 전달 `extra_generic` | `_normalize_tokens` |

처리 순서: NFKC·casefold → 회사표시 기호 `(주)` 제거 → 기호·구두점을 공백으로 → 토큰화(한글/영문/숫자 경계 분리, 한자·이모지 토큰 폐기) → 연속 중복 토큰 제거(=제거 전) → 보통명칭 제거(=제거 후, 비면 제거 전 사용) → 토큰별 읽기 → 병기 판정 → 후보 조립 → 음절 유사도 최댓값.

## 2. 설계 상수와 근거 (검토·조정 대상)

| 상수 | 현재값 | 근거 |
|---|---|---|
| `POSITION_WEIGHTS` | n≤2: (3.0, 1.5) / 3~4: (2.0, 1.5, 1.0, 1.0) / n≥5: (1.5, 1.2, 1.0…) | ② 첫음절 2배가 기준선. 2음절 상표는 첫음절이 사실상 전부라 3배, 5음절 이상은 앞음절 강세가 상대적으로 약해 1.5배. n 은 긴 쪽 음절 수 |
| 치환 비용 | 초성 0 / 0.5(유사) / 1.0 · 중성 0 / **0.1(합류)** / 0.5(유사) / 1.0 · 종성 0 / **0.25(비음끼리 또는 같은 대표음)** / 0.5(한쪽만 있음·다른 대표음) — 최대 2.5 | 유사 자모는 절반, 종성은 초·중성보다 청각적 비중이 낮음. 중성·종성은 2단계 |
| `COST_INDEL` | 2.5 | 음절 최대 치환 비용과 동일(삽입·삭제가 치환보다 싸지 않게) |
| `CHO_SIMILAR_PAIRS` | {ㄱㅋㄲ}{ㄷㅌㄸ}{ㅂㅍㅃ}{ㅈㅊㅉ}{ㅅㅆ}{ㄹㄴ}**{ㄴㅁ}** 그룹 내 쌍(15쌍) | 같은 조음 위치의 평음·격음·경음, 유음·비음(ㄹㄴ), 비음끼리(ㄴㅁ) 혼동 |
| `JUNG_SIMILAR_PAIRS` (0.5) | (ㅓㅏ)(ㅗㅜ)(ㅡㅜ)(ㅕㅑ)(ㅝㅘ) + **y계열** (ㅑㅏ)(ㅕㅓ)(ㅛㅗ)(ㅠㅜ) + **w계열** (ㅘㅏ)(ㅝㅓ)(ㅙㅐ)(ㅞㅔ)(ㅚㅔ)(ㅟㅣ) — 15쌍 | 인접 모음, 그리고 반모음만 다르고 핵모음이 같은 쌍(리쥬/리주) |
| `JUNG_MERGED_PAIRS` (**0.1**) | (ㅐㅔ)(ㅒㅖ)(ㅙㅞ)(ㅙㅚ)(ㅞㅚ) | 현대 서울말에서 완전히 합류해 청감상 동일한 쌍. 0.1 은 정확 일치가 순위에서 앞서도록 남기는 최소 비용(2026-09-17 결정, v1.1 의 0.25 는 1음절 게/개가 0.90 에 그침). v1 에서는 유사(0.5)에 섞여 있었음 |
| `JONG_REP_GROUPS` | 대표음 7그룹(첫 원소가 대표음) | 받침 대표음(예: 낚/낙) |
| `JONG_NASAL` (**0.25**) | {ㄴ, ㅁ, ㅇ} — 양쪽 받침의 대표음이 모두 비음이면 0.25, 대표음 규칙보다 우선 | 비음 위치동화(신문→[심문], 한강→[항강]) |
| `PAIRED_THRESHOLD` | 0.8 | ⑤ 병기 판정. 낮추면 병기 오탐(다른 영문을 한글로 오인) ↑ |
| `MAX_CANDIDATES` / `MAX_SYLLABLES` | 16 / 40 | ③ 조합 폭주 방지, 긴 슬로건형 상표명 상한 |
| `UNIVERSAL_GENERIC` | 회사 형태·부가어·영문 기능어 31개 | 요부관찰. 상품 의존 보통명칭은 여기 넣지 않고 `extra_generic` 으로 |
| `KOREAN_BRAND_ROMANIZATION` | 국내 브랜드 로마자 **91개** (`korean_brands.py`) | 룰로 읽을 수 없는 한국어 로마자(samsung, hyundai …). 씨앗 110개 중 룰 결과와 같은 33개(kakao, naver …)는 중복이라 제외한 77개 + 로마자 캐기 승인분 10개(gudaero, chengdamsu, yumbbokki, nakwon, luciel, netmarble, petitzel, heyalfun, honsul, sancheon) + 유명 브랜드 목록 교차 확인 4개(sangmidang, eland, woowa, baedal). 룰보다 먼저 적용 |
| `KOREAN_PLACE_ROMANIZATION` | 국내 지명 로마자 **34개** (`korean_brands.py`) | 광역·서울 안 지명·시군·국호 39개 중 룰 결과와 같은 5개(sejong, insadong, songdo, sokcho, mokpo) 제외. 브랜드표와 같은 단계(룰보다 먼저). **향후 식별력 필터(현저한 지리적 명칭)에서 재사용 예정** |
| `G2P_EXCEPTIONS` | 기능어·수사·약어 24개 + 외래어 관용 표기 15개 = 39개 | 룰로 맞추기 어려운 불규칙. 브랜드(hyundai/lotte/kia)는 브랜드 표로 이동. 관용 표기(pilates, ballet, etoile, curry, atelier, gourmet, poke, musical, salon, baseball, together)는 로마자 캐기에서 확인해 승인, coffee→커피 는 룰의 o→ㅗ 기본값이 맞지 않는 불규칙, paris·baguette·republica 는 유명 브랜드 목록 교차 확인에서 승인 |
| `LETTER_READING_MAX_LEN` | **3** (v1: 5) | 낱자 읽기(에이비씨) 추가 기준. 모음 없는 토큰은 길이 무관. r 은 알/아르 두 후보 |

점수 = max(0, 1 − 거리/최대거리), 최대거리 = Σ_{p<n} w[p]·2.5. 연산 비용에 `w[min(i, j)]` 를 곱해 대칭을 보장한다.

벤치마크 규칙: `x1_report.py` 의 20단어 표본은 `g2p_benchmark`(브랜드·지명 표와 예외 사전을 모두 끈 순수 룰)로 측정한다. 표에 단어를 넣어도 벤치마크가 오르지 않도록 테스트(`test_benchmark_disables_exception_and_brand_tables`)가 이 계약을 검증한다.

## 4. 알려진 한계

1. **한자 미지원(v1)**: 한자 토큰은 버린다. 순수 한자 상표명은 `has_pronunciation` False. 데이터 1,100건 중 한자 포함 1건(0.1%)이라 후순위.
2. **G2P 는 근사**: 20단어 표본(순수 룰) 정확 일치 15/20, 평균 음절 유사도 0.957. 실패 유형은 한국 브랜드 로마자(SAMSUNG→샘성 — 브랜드 표로 보완), 불규칙 모음(COFFEE→코피 — 예외 사전으로 보완, NIKE→나이크), 어말 s(PARIS→파리스). 데이터 표본에서 관찰된 룰 공백 중 seoul·together·baseball·pilates·heyalfun 은 v1.2 에서 표·예외 사전으로 흡수했고, group→그라웁, airline→에얼린 은 미수정으로 남아 있다.
3. **보통명칭은 `extra_generic` 의존**: "블루 커피 / 레드 커피"는 `extra_generic={"커피"}` 없이는 토큰 후보 "커피"끼리 1.0 이 된다. 1글자 토큰 문제(실온K슐랭 / K8 REFOREST)는 v1.1 에서 해결했지만, **2글자 이상 공통 토큰(프로, 치킨, 클럽 등)은 여전히 1.0** 이 될 수 있다 → 식별력 필터(다빈-3)의 보통명칭 집합을 넘겨야 한다.
4. **붙여쓴 결합어는 분리 불가**: "서울바쿠테 / 바쿠테" 0.474, "스타벅스 / 스타벅스커피" 0.701. 형태소 분석을 쓰지 않으므로 공백·기호·문자 종류 경계로만 나눈다.
5. **불가분 결합은 근사**: 결합 여부를 판단하지 않고 "전체 결합음을 항상 후보에 유지"로 대신한다.
6. **낱자 읽기 상한 3자**: 모음이 있는 4자 이상 약어(NASA, ASUS 등)는 룰 읽기만 붙는다(나사, 아수스). 모음 없는 약어(KBS, HSBC)는 길이와 무관하게 낱자 읽기가 붙는다.

## 5. 검토 대기 (사람 결정 필요)

### 5-1. 유사 자모 보류 4개 — 정답 데이터(다빈-1)로 검증 후 결정, 지금은 넣지 않음

| 후보 | 보류 이유 |
|---|---|
| 초성 (ㅎ,ㅇ) | ㅎ 약화·탈락은 모음 사이(유성음 사이)에서만 일어난다. 어두에서는 뚜렷이 구별되므로 위치 조건 없이 넣으면 오탐(호/오, 하나/아나) |
| 중성 (ㅡ,ㅓ) | 외래어 표기 혼동(버스/브스)은 있으나 표준 발음에서는 구별. 혼동 사례 빈도를 데이터로 확인 필요 |
| 중성 (ㅡ,ㅣ) | 방언(경상) 합류. 판례가 표준 발음을 기준으로 하므로 근거 부족 |
| 종성 불파음 ㄱ/ㄷ/ㅂ 간 유사 | 어말 불파로 청각 구별이 약하다는 근거는 있으나, 조음 위치가 다르고 현재 종성 비용(0.5)이 이미 낮아 효과·부작용을 측정한 뒤 결정 |

### 5-2. 결정 완료 (2026-09-17)

- **서울커피 / SEOUL COFFEE**: 지명표로 SEOUL→서울 은 되지만 COFFEE 가 룰로 "코피"(ㅓ/ㅗ 는 유사 쌍이 아님)라 0.927 이었다. `G2P_EXCEPTIONS` 에 coffee→커피 추가로 결정(외래어 관용 표기, 룰의 o→ㅗ 기본값이 맞지 않는 불규칙) → 1.000. 부수 효과: 커피빈/COFFEE BEAN 0.822→1.000, 스타벅스커피/STARBUCKS COFFEE 0.940→1.000(둘 다 테스트로 고정), 표본 30쌍 평균 변화 없음. 벤치마크는 순수 룰이라 COFFEE 행(0.733)은 그대로.
- **1음절 합류 쌍 게/개**: 합류 비용 0.25 에서는 0.900 → `COST_JUNG_MERGED`=0.1 로 결정해 0.960. 부수 효과는 2음절 첫음절 합류 쌍(메가/매가 등) 0.933→0.973, 표본 평균 +0.0002 이내.

### 5-3. 로마자 후보 84행 (§6 2단계) — 23행(토큰 21개)을 v1.2 에서 승인·반영(브랜드표 10, 예외 사전 11). 나머지 61행은 미승인 상태로 CSV 에 남아 있다.

### 5-4. `extra_generic` 매칭 범위 — 통합 시 결정

현재 `extra_generic` 은 정규화된 **원 토큰**에만 매칭한다. 다빈-3(식별력 필터)이 한글 보통명칭 목록(예: {"커피"})을 넘길 때 영문 토큰 coffee 는 걸리지 않는다. 매칭을 원 토큰뿐 아니라 **토큰의 읽기**(coffee→커피)에도 적용할지는 통합 시 결정한다. 적용하면 "SEOUL COFFEE" 에서 coffee 가 제거돼 요부 "서울"만 대비하게 된다.

## 8. 통합 모델 담당자용 인터페이스 안내

- `phonetic_similarity(a, b, *, extra_generic=frozenset())` — 대칭·결정적, 어떤 문자열에도 float 반환. 후보가 한쪽이라도 없으면 0.0 (유사도 0 이 아니라 **비교 불가**의 의미이므로 `has_pronunciation` 으로 먼저 걸러라).
- `has_pronunciation(name)` — 한글 음절 후보가 하나라도 있으면 True. False 인 상표(순수 도형·한자만·기호만)는 X1 을 결측 처리하고 다른 축만으로 판단한다.
- `extra_generic` — 식별력 필터(다빈-3)나 상품 정보에서 얻은 **상품 의존 보통명칭 집합**(예: `{"커피", "카페"}`)을 넘긴다. 양쪽 상표명에 같은 집합을 적용한다. 항목은 내부에서 NFKC·casefold 정규화되며 다중 토큰("커피 전문점")은 연속 열로 매칭한다.
- `pronunciation_candidates(name)` — 디버깅·화면 표시용 후보 목록. 결과 화면에 "어떤 발음으로 비교했는지" 근거로 보여줄 수 있다.
- 성능: 데이터 상표명 1,000쌍 0.21초(cold, v1 0.51초 — 낱자 읽기 감소로 후보가 줄어 빨라짐). 내부 lru_cache 로 반복 호출은 더 빠르다.
- 서비스 연결(2026-09-17, 최소 통합): `backend/src/core/phonetic_search.py` 가 기동 시 DB 상표명 중 `has_pronunciation` 인 것만 `pronunciation_candidates` 로 캐시하고, `POST /phonetic-search` 가 입력과 각 레코드의 `phonetic_similarity` 상위 후보를 돌려준다(하한 `MARKLENS_PHONETIC_MIN_SIMILARITY` 기본 0.5). 프런트는 상표명 확인 패널에 "발음(호칭)이 비슷한 등록상표" 섹션으로 표시한다. 공개 함수 세 개만 사용하며 검색 등급에는 미반영.
- 통합 시 주의: 점수는 교정 전 원점수다. 로지스틱 회귀 학습 전 §2 상수와 §5 보류 항목은 정답 데이터(다빈-1)로 재검토한다.
