# MarkLens X2 외관 — 현재 구현 요약과 심결 이미지 쌍 벤치마크 v0

기준일 2026-10-08 · 상태: **v0 기준선 + v1 ① 표장 라벨 보정·요부 분리(§7) + v1 ② 전체 이미지 변형·OCR
진단·게이팅(§8) 완료 + 문자 외관(철자) 축 함수 `x2_ortho.py`(§9; 2026-11-20 철자 v2 시도 — v1 유지). 서비스 반영은 다음 PR** · 브랜치
`feat/x2-benchmark`(v0, PR #33 병합) → `feat/x2-v1`(v1 ①·②, PR #34 병합) → `feat/axes-benchmark`(§9)

X2(외관)는 1학기에 OpenCLIP 임베딩 + FAISS 코사인 검색으로 구현돼 현재 서비스(통합 검색 `POST /search/v2` 의 이미지 후보 풀)에
쓰이고 있지만, 그 점수가 심판원의 외관 판단과 얼마나 맞는지는 잰 적이 없었다. 이 문서는 (1) 현재
X2 구현을 요약하고, (2) 심결문 PDF에 내장된 양쪽 표장 이미지로 만든 벤치마크의 정의·추출 방법·
커버리지, (3) v0 결과와 한계를 적는다. 수치는 모두 2026-10-08 실측이다. 데이터(`ml/data/trials/`)는
저장소에 넣지 않는다.

## 1. 현재 X2 구현(1학기 → 현재 서비스)

| 항목 | 내용 | 코드 |
|---|---|---|
| 모델 | OpenCLIP `ViT-B-32`, pretrained `laion2b_s34b_b79k`, CPU 추론 | `ml/src/contracts.py`, `ml/src/embedding.py` |
| 임베딩 | 512차원 float32, L2 정규화. 계약 `openclip-image-v2` | `encode_image()` |
| 전처리 계약(기본) | `clip-center-crop-v1`: EXIF 회전 보정 → 알파는 흰 배경에 합성 → RGB(최소 32px, 최대 4096px, 빈·균일 이미지 거부: 채널 범위 ≥ 4, 표준편차 ≥ 1) → OpenCLIP validation transform(짧은 변 224 리사이즈 + 중앙 crop + 정규화) | `ml/src/preprocess.py` `prepare_model_views()` |
| 전처리 계약(대안) | `global-letterbox-dual-bg-v1`: 224 정사각 레터박스(crop 없음), 알파가 있으면 흰·검 배경 두 view 임베딩을 평균 후 재정규화. 2026-08 paired 비교에서 legacy 와 유의한 차이가 없어 **채택하지 않음**(`ml/evaluation/README.md`) | 같은 파일 |
| 코사인 | FAISS `IndexFlatIP`(inner product) — 정규화 벡터의 내적 = 코사인. `build_index()`·`search()`가 벡터 정규화·metric 을 검증한다 | `ml/src/search.py` |
| 서비스 | 통합 검색 v2 후보 풀: 질의 임베딩(`engine.encode_image`) → FAISS 상위 20(`engine.search`) → 후보 축 `x2_img` + `score_results()`(top-1 코사인의 단조 임계값으로 4단계 상태 → `overall.visual_status`) | `backend/src/core/multi_search.py`, `backend/src/core/engine.py`, `ml/src/scoring.py` |

1학기 관찰(설계결정기록 §5): 무관한 로고 사이에도 코사인 0.43–0.59 의 베이스라인이 있어 절대값보다
격차가 신호다. 이번 벤치마크는 그 절대값이 심결의 유사/비유사를 가르는지를 직접 잰 것이다.

## 2. 벤치마크 정의

- **질문**: 특허심판원이 유사/비유사로 결론 낸 실제 표장 쌍에서, 현재 X2 코사인이 그 결론을 가르는가.
- **데이터**: `ml/data/trials/labels.csv`(심결례 843건·1,024행) 중 LLM 이중 라벨(pass a·b)이 **일치하고
  둘 다 유사·비유사**인 350행(320건). 제외·불일치 행은 뺀다. 라벨은 심결의 **최종 결론**이다(§6 참고).
- **쌍**: 행마다 (이 사건 출원·등록상표 `this`, 상대 표장). 상대는 거절결정불복·무효면 선등록상표
  `prior_N`(행의 `상표B_번호` ↔ 색인 등록번호로 매칭, 없으면 순번), 권리범위확인이면 확인대상표장
  `target`. 양쪽 이미지가 있는 행만 쌍이 된다.
- **점수**: `ml/src/embedding.py` 의 `encode_image`(전처리 계약 포함)와 `ml/src/search.py` 의
  `build_index`·`search` 를 그대로 import 해 쌍마다 FAISS inner product 를 읽는다 — 서비스와 같은
  경로이며 별도 구현은 없다. 임베딩은 `ml/data/trials/x2_cache_v0.npz`(파일 sha256 키, 모델·전처리
  계약이 다르면 폐기)에 저장해 변형 실험에서 재사용한다.
- **지표**: ROC AUC(Mann–Whitney 순위, 동점 0.5), 유사·비유사 점수 분포(평균·중앙값·사분위), 정확도가
  최대인 임계값과 그 정확도, 분리도 = 유사 Q1 − 비유사 Q3(양수면 사분위 범위가 겹치지 않음), 기준선 =
  라벨을 섞은 AUC(200회, 평균·5–95%).
- **부분집합**: (a) 전체 (b) 판단축에 '외관' 포함 (c) 상표유형 도형·결합-도형요부 (d) 문자 (e) 연결
  신뢰도 high. **(b)·(c)가 X2 의 공정한 시험대다** — 문자상표 쌍은 호칭·관념으로 갈린 사건이라 글자
  이미지의 코사인이 결론과 맞을 이유가 없고, (a)는 그런 쌍이 절반 넘게 섞여 있다.
- 상표유형은 `상표유형_확정`(사람·LLM 라벨), 없으면 `상표유형_추정`(정규식)을 쓰고 출처를 적는다.

## 3. 이미지 추출·연결(`ml/scripts/trials_extract_images.py`)

## 5. v0 결과(현재 X2, 전처리 `clip-center-crop-v1`)

`ml/venv/bin/python ml/scripts/x2_benchmark.py` → `ml/data/trials/x2_benchmark_v0.json`, `x2_hist_v0.png`.

| 부분집합 | n (유사/비유사) | AUC | 섞은 라벨 AUC(5–95%) | 정확도 최대 임계값 → 정확도 | 유사 중앙값 | 비유사 중앙값 | 분리도 |

읽는 법과 해석:

- **전체(a) 0.51** — 라벨을 섞은 기준선(0.50, 5–95% 0.45–0.56)과 구별되지 않는다. 임계값 0.218 의
  "정확도 0.615" 는 유사가 59% 라 거의 모두 유사로 찍은 값이다.
- **외관축(b) 0.62** — 기준선 범위(0.40–0.59) 바깥이라 신호는 있지만 약하다. 유사 중앙값 0.59 vs
  비유사 0.54. 임계값 0.845 의 정확도 0.73 은 비유사가 71% 라 "전부 비유사"(0.71)와 거의 같다 —
  임계값으로 쓸 수 없다.
- **도형(c) 0.50** — n 34 로 기준선 범위가 0.33–0.69 까지 벌어져 결론을 내릴 수 없다. 표본 확대가 먼저다.
- **문자(d) 0.56** — 글자 이미지끼리의 전역 코사인이 결론과 거의 무관함을 확인(예상대로).
- 분리도는 모든 부분집합에서 음수 — 유사의 하위 25% 와 비유사의 상위 25% 가 넓게 겹친다
  (히스토그램 `x2_hist_v0.png`: 두 분포가 0.3–0.7 에 겹쳐 있다).
- **결론**: 현재 X2(중앙 crop + CLIP 전역 임베딩의 코사인)는 심결의 외관 판단을 재현하지 못한다.
  이 표가 전처리·crop·마스킹 변형 실험의 **기준선**이며, 변형은 같은 쌍·같은 지표로 (b)·(c)에서 비교한다.

## 6. 한계

- **문자상표 이미지 없음**: 구성이 글자로만 적힌 표장은 합성하지 않아 쌍에 없다(18행). 반대로 글자를
  이미지로 넣은 문서가 많아 쌍의 54%(155)가 문자상표다 — (a)는 X2 의 시험대가 아니다.
- **연결 오류 가능성**: 규칙 기반 연결이다. QA 30쌍 표본 세 번이 모두 맞았지만 전수 확인은 아니고,
  low 2쌍과 순번 매칭 6쌍은 틀릴 수 있다. 쌍 파일의 `연결신뢰도`·`매칭` 열로 걸러 쓴다.
- **실사용 사진**: 권리범위확인의 확인대상표장은 40% 가 상품·간판·포장·화면 캡처 사진으로 추정된다.
  표장 자체가 아니라 사용 장면과 비교하므로 X2 에 불리하고, 판례의 "표장 대비" 와도 다르다.
- **이격적 관찰 미반영**: 판례는 시간·장소를 달리하는 이격적 관찰과 요부 관찰로 외관을 본다. 코사인은
  두 이미지를 나란히 놓은 전역 픽셀 유사로, 요부(지배적 부분)만 떼어 보지 않는다.
- **라벨은 최종 결론**: 판단축이 '상품' 뿐인 24쌍은 표장을 대비하지 않은 사건이고, "표장 유사·상품
  비유사" 메모가 붙은 비유사 6쌍은 외관이 유사해도 비유사로 적혀 있다. (b)는 이들을 자연히 제외한다.
  판단축이 비어 있는 7쌍(권리범위확인의 축 미기재)도 (b)에 들지 않는다.
- **소형 이미지 제외**: 40px 규칙으로 40행이 빠진다(가는 문자 표장). 32px 면 +20쌍.
- **한 표장 한 이미지**: 입체상표의 사시도·정면도 등 여러 view(2024100003331)는 가장 큰 하나만 쓴다.
- **해상도**: 심결문 이미지는 대부분 100–300px 의 JPEG/PNG 로, 서비스 입력(사용자 업로드)보다 작다.
- **표본**: 유사 170/비유사 116, 권리범위확인 160 으로 종류가 치우쳤고 도형 쌍은 34뿐이다. 라벨은
  LLM 이중 라벨이다(사람 검증은 2026-10-11 마감 — 표본 37/40, 통합 모델 설계 §4-3).

### 7.2 요부 분리 방법

| 단계 | 규칙 |
|---|---|
| 글자 검출·인식 | easyocr 1.7.2(CRAFT 검출 + ko·en 인식, CPU, 모델은 첫 실행 때 내려받음). 짧은 변이 160px 미만이면 키워 넣고 좌표를 되돌린다. 인식 확신도 < 0.2 인 박스는 글자가 아니다(도형에서 전체 이미지 박스가 0.02 로 잡히는 것을 실측) |
| `text_ratio` | 글자 박스 합집합 면적 / 전체. `ocr_text` = 박스 글자를 읽기 순서(y→x)로 이은 것 |
| 도형 크롭 | 글자 박스를 배경(테두리 2px 띠의 채널 중앙값)으로 지우고, 배경과 24 넘게 다른 픽셀의 bbox 를 `fig.png` 로 저장. `fig_ratio` = bbox 면적 / 전체 |
| 자동 유형 | text_ratio < 0.05 → 도형, fig_ratio < 0.08 → 문자(크롭 없음), 그 외 결합(둘 중 큰 쪽이 요부) |
| `x2_whole` | v0 그대로(전체 이미지 CLIP 코사인, 같은 캐시) |
| `x2_fig` | 양쪽 도형 크롭이 있을 때 CLIP 코사인(같은 `encode_image`·FAISS 경로). 없으면 결측 |
| `x2_text_ortho` | 양쪽 `ocr_text` 를 X1 `normalize_name`(NFKC·casefold·기호·회사표시 제거)으로 정리하고 한글은 자모로 푼 뒤 문자 단위 정규화 편집거리 1 − d/max. OCR 실패면 결측 |
| `x2_rule_auto` / `x2_rule_llm` | 이 사건 표장의 유형(자동 / LLM)이 문자면 text_ortho, 도형이면 fig, 결합이면 둘의 max. 결측이면 whole 로 대체(횟수를 센다) |

산출: `image_parts.csv`(이미지 662건), `image_pairs_v1.csv`(쌍 306 + 특징), `x2_split_qa.png`(사진 쌍

### 7.5 해석과 한계

- **라벨 보정은 whole 을 바꾸지 못했다.** 전체 0.495, 외관축 0.633 — v0(0.51/0.62)와 같다. 결론이
  상품으로 갈린 22쌍을 빼고 "표장 유사" 7쌍을 뒤집어도, 전체 이미지 코사인은 표장 판단과 무관하다.
- **철자 유사(`x2_text_ortho`)가 가장 강한 신호다.** 외관축 0.72(0.57–0.86), 문자 0.60, 전체 0.55.
  외관축에서 유사 중앙값 0.57 vs 비유사 0.25, 임계값 0.93 에서 정확도 0.81(비유사 비율 0.71 기저보다
  +10p). 다만 이것은 "눈에 보이는 생김새"라기보다 **글자 구성**의 유사라서 X1 호칭과 정보가 겹친다 —
  통합 모델에서 X1 과 함께 넣으면 공선성을 봐야 한다.
- **도형 크롭(`x2_fig`)은 아직 판단 불가.** 양쪽 크롭이 다 있는 쌍이 80, 도형 부분집합은 29(유사
  11·비유사 18)로 CI 가 0.32–0.77 이다. 사진 부분집합에서는 0.20 으로 **뒤집힌다**: 사진은 글자를
  지워도 상품·배경이 남아 크롭이 "도형"이 아니고, 깨끗한 등록 표장과 비교하면 오히려 멀어진다.
- **규칙 결합은 whole 보다 조금 높을 뿐이다.** 외관축 0.64(auto)·0.66(llm), 전체 0.51–0.52. CI 가
  whole 과 겹친다. 유형 판정 자체가 76% 라 규칙의 상한이 낮다.
- 한계: OCR 오인식("지깊이")과 양식화 글자 미검출(결합 → 도형 26건), 임계값 0.05/0.08 은 보정하지
  않은 값, 요부 판단은 면적 비율로 불가, 사진 표장은 분리 자체가 성립하지 않음, 도형 표본 35·크롭 쌍
  80 으로 작음, 라벨은 LLM 이중 라벨(사람 검증 전). easyocr 는 실험 전용 의존성(서비스 미사용).

## 9. 문자 외관(철자) 축 함수 `ml/src/axes/x2_ortho.py` (2026-10-08, `feat/axes-benchmark`)

§7 의 `x2_text_ortho`(OCR 글자 기준 실험 특징)를 공통 규약(문자열 2개 → 0–1, 순수 함수·대칭·결정적·예외 없음, 표준 라이브러리만)의 축 함수로 올렸다. 서비스 연결은 없고 통합 모델 입력(`pairs_features.csv` 의 `x2_text`)이다.

- **판례 근거**: 표장 유사는 외관·호칭·관념의 전체적·객관적·이격적 관찰(대법원 97후3050 등). 문자상표의 외관은 글자의 구성·배열이 시각적으로 비슷한지의 문제이므로 발음(G2P)을 쓰지 않고 정규화한 철자를 비교한다. X1 과 재는 것이 다르다 — XSR/XSL 은 철자 0.667·호칭은 별개, 나이키/NIKE 는 호칭 0.91·철자 0.0, 스타벅스/STARBUCKS 0.0(한영 병기는 X1 이 잇는다).
- **방법**: X1 `normalize_name`(NFKC·casefold·회사 형태·부가어·영문 기능어·`extra_generic` 제거, 한자·기호 버림) → 후보 = 토큰을 붙인 전체 문자열 + 토큰이 3개 이하면 2자 이상인 각 토큰(분리관찰, X1 `MAX_TOKENS_FOR_SPLIT` 과 같은 상한) → 한글은 X1 유틸로 초·중·종성 자모 분해 → 후보 쌍의 문자 단위 정규화 편집거리 유사도 1 − d/max 의 최댓값. 공개 API `orthographic_similarity(a, b, *, extra_generic=frozenset())`, `has_spelling(name)`(글자 토큰 없음 → 결측), `spelling_candidates(name)`(디버깅).
- **회귀**: 토큰 후보가 전체 문자열을 넘지 못하는 입력(스타벅스/스타박스 0.889, XSR/XSL 0.667, 커피빈/커피 빈 1.0, UNDEFEATED/UNDFTD …)에서 §7 `x2_split.ortho_similarity` 와 같은 값. 토큰 후보는 점수를 올리기만 한다(닥치고 떡볶이/떡볶이 명가 → 1.0). 테스트 `ml/tests/test_x2_ortho.py` 함수 16개(매개변수 전개 109건): 자기 1.0·대칭·범위·예외 없음, 스타벅스/스타박스 ≥ 0.8, 나이키/NIKE·스타벅스/STARBUCKS ≤ 0.3, BLUE COFFEE/RED COFFEE 는 `extra_generic` {커피} 로 1.0 → ≤ 0.3, 기호·한자만은 결측.
- **심결례 벤치마크 현재 값(2026-11-19, 1·2차 597행 — 2차 상대 표장 명칭 보강 뒤, 통합 모델 설계 §4-5)**: `x2_text` (a) 0.57 (0.51–0.64, n 453 — 사건 단위 CI; 사건 가중 상한 3 이면 0.56) · (b) 판단축 외관 0.72 (0.62–0.82, n 178) · `x2_text_d` 0.58 · 문자계 0.58(외관축 0.77) · 2차만 0.59 · 현실 분포 0.81 (0.78–0.84). 1차만(같은 방법) 0.56 (0.48–0.64, n 287)·(b) 0.73 과 CI 가 겹친다. 같은 날 오전 명칭 조회 전(2차 이름 축 51행) 값은 (a) 0.55·(b) 0.71 이었다. 아래는 2026-10-08 측정 기록이다.
- **심결례 벤치마크(상표명 기준, 통합 모델 설계 §4-1)**: 표장 라벨 AUC (a) 전체 0.50 (0.44–0.57, n 290) · (b) 판단축에 외관 포함 **0.65** (0.52–0.77, n 119 — 유사 26·비유사 93) · (c) 0.51. 같은 쌍의 전체 이미지 CLIP(`x2_whole`)은 (b) 0.63 (0.53–0.73, n 131), 도형 크롭(`x2_fig`)은 (b) 0.49 (n 45). OCR 글자 기준 §7.4 의 0.72(n 130)보다 낮은 것은 상표명에 도형 안 글자가 빠지거나 회사명·병기가 붙는 쌍이 섞이기 때문이고, (b)의 라벨 쏠림(외관을 적은 쌍은 대부분 비유사)은 §7.1 과 같다. X1 과 스피어만 0.63(공선성), 전체 이미지와 0.25.
