## 프론트 현재 상태 (2026-07-07) — ★프론트-4·5가 이미 구현됨

`frontend/`에 Next.js 앱이 신규 구현되어 실제 백엔드와 연동 검증까지 끝났다 (**아직 미커밋** — 팀 확인 후 기능 브랜치로 PR).

| 항목 | 내용 |
|---|---|
| 스택 | Next.js 16 (App Router, Turbopack) · React 19 · TypeScript · Tailwind v4 · **Pretendard 가변 폰트(로컬 번들)** |
| 디자인 | "토스 결" — 회색 바탕(#F2F4F6) + 흰 카드(r20) + 토스 블루(#3182F6), 대화형 카피, 모바일 우선 560px 칼럼. 시안: [디자인 아티팩트 v2](https://claude.ai/code/artifact/1173558d-c0d5-4c76-b578-4209182a31d4) |

| 검증 | 헤드리스 Chrome E2E: 업로드→검색→결과 3층 렌더 9/9 어서션 + 오류(서버 400 detail 표기) 통과 |

### 파일 구조와 각 파일의 역할
```
frontend/
├ app/
│ ├ layout.tsx        # Pretendard(next/font/local) + 메타데이터. 폰트: app/fonts/PretendardVariable.woff2
│ ├ page.tsx          # 상태머신(idle/loading/result/error), 헤더·푸터
│ └ globals.css       # 디자인 토큰(@theme: ink/sub/muted/blue/caution/review/safe…) + 애니메이션
├ components/
│ ├ SearchForm.tsx    # 입력: 드래그 업로드+미리보기, 상표명, 지정상품 칩(추천+직접입력), top_k 세그먼트
│ ├ ResultView.tsx    # 결과 3층: 등급 히어로(4등급 매핑)+warnings / 매치 목록(썸네일·%·행 펼침) / 상세 접힘
│ ├ LoadingView.tsx   # 펄스 링 + 순환 메시지 3종
│ └ ErrorView.tsx     # 서버 detail 메시지 + HTTP 상태 칩 + 재시도/처음으로
└ lib/api.ts          # 백엔드 스키마 타입(한글 필드 그대로) + searchTrademark() + 에러 매핑 + imageUrl()
```

실행: `cd frontend && npm run dev` (포트 3000 점유 시 `-p 3100`). 백엔드 주소는 `NEXT_PUBLIC_API_BASE`(기본 `http://127.0.0.1:8000`).

### 설계 결정 (알아둘 것)
- **백엔드가 아직 안 받는 입력(상표명·지정상품)도 UI에 이미 존재** — "다축 분석에 반영 예정" 배지로 정직하게 표기. 백엔드-9 확장 시 `lib/api.ts`의 FormData에 필드만 추가하면 됨.
- 등급 4종(CAUTION/REVIEW/LOW/SAFE)별 헤드라인·색·이모지 매핑은 `ResultView.tsx`의 `GRADE_VIEW` 한 곳. scoring.py의 `warnings` 배열도 그대로 렌더됨.
- 유사도 % 색상 밴드: ≥75% 빨강, ≥55% 주황, 미만 파랑 — scoring 임계값과 일치시켜 둠. **F(재보정)에서 임계값이 바뀌면 `simTone()`도 같이 갱신할 것.**
- 데이터 범위 문구는 백엔드 `dataset_info`를 그대로 출력 — 하드코딩 아님(백엔드-6에서 갱신하면 자동 반영).

## 프론트-2. 상품↔유사군 변환표 ⚡즉시 · 최우선

**목표**: [상품명, 류, 유사군코드] 표 — 프론트-6(검색 UI)과 프론트-8(자카드)이 공동 사용.
1. 지식재산처 홈페이지 > 지식재산제도 > 분류코드조회 > 상품분류코드 > **"고시상품명칭 13판(2026)"** 무료 다운로드 (엑셀일 가능성 높음 → pandas/openpyxl로 파싱)
2. ⚠️ **한 상품에 유사군 여러 개 가능**(예: 화장품 = G1201, S120907, S128302) → 반드시 1:N 구조:
```json
[{ "name": "화장품", "nice_class": 3, "similarity_codes": ["G1201", "S120907", "S128302"] }]
```
3. 저장: `shared/goods_map.json`(또는 `ml/data/` — 고시 데이터는 공공 데이터라 커밋 가능 여부 확인 후 결정, 애매하면 shared/에 생성 스크립트+원본 URL만 커밋)
4. 완료 후 다빈에게 검증 요청(다빈-4: 1:N 구조 표본 확인)

**완료 기준**: JSON 로드 → "화장품" 검색 → 유사군 3개가 나온다.

## 프론트-6. 지정상품 입력 UI 완성 (프론트-2 후)

현재 `SearchForm.tsx`의 지정상품 칩은 임시(하드코딩 추천 5종 + 자유 입력). 변환표가 생기면:
1. `shared/goods_map.json`을 정적 import(또는 `/public`에 두고 fetch) → 클라이언트 검색: 초성/부분일치 필터 (수만 건이면 `Fuse.js` 또는 단순 `includes` + 상위 20개 컷)
2. 2단계 탐색: 류(1~45) 목록 → 해당 류의 고시상품 목록 (현재 "직접 분류 고르기" 칩 자리에 바텀시트/모달로)
3. 선택 결과를 **유사군 코드 배열로 변환해 상태에 보관** — 전송 형태 예: `similarity_codes: ["G0502","S120602"]` (백엔드-9 계약과 맞춤)
4. 칩에는 사람이 읽는 상품명 + 코드 툴팁 표기 유지

**완료 기준**: "커피" 검색 → 후보 선택 → 칩 생성 → 제출 payload에 유사군 코드 배열이 담긴다(백엔드가 받기 전까지는 콘솔 확인).
