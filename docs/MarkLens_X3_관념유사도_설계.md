# MarkLens X3 관념 유사도 설계

- 기준일: 2026-09-30 (v1.1) · 구현: `ml/src/axes/x3_semantic.py` · 정규화 공유: `ml/src/axes/x1_phonetic.py` `normalize_name`(X1 v1.5) · 테스트: `ml/tests/test_x3_semantic.py`(A 불변식·B 게이트·C 벤치마크(실제 모델)·D 정규화/재보정) · 벤치마크·성능: `ml/scripts/x3_benchmark.py`
- 규약(공통-2): `semantic_similarity(a, b, *, extra_generic=frozenset()) -> float` 0.0~1.0(높을수록 관념 유사), 순수 함수·대칭·결정적, 어떤 문자열에도 예외 없음. `has_meaning(name) -> bool` 은 X1 `has_pronunciation` 과 같은 결측 판정이다.
- 의존성: `sentence-transformers` 6.1.0(transformers·scikit-learn·scipy 동반), `wordfreq` 3.1.1(MIT, 한국어는 표제어 직접 조회라 MeCab 불필요). 모델은 `MARKLENS_X3_MODEL` 로 교체, CI 는 `MARKLENS_FAKE_ML=1` 가짜 임베더.

## 1. 판례상 관념 유사 → 구현

- **관념 유사**: 두 표장이 지니는 의미·내용이 같거나 비슷해 수요자가 같은 뜻으로 인식하는 경우. 한글·영문처럼 표기가 달라도 뜻이 같으면 관념이 유사하다(왕/KING, 사과/APPLE). 외관·호칭·관념 중 하나만 유사해도 거래 실정상 출처 오인·혼동 우려가 있으면 유사 상표로 본다(X1 설계 문서 §1 과 같은 판단 틀).
- **조어·기호·도형**: 특정한 관념이 없어 관념 대비 자체가 성립하지 않는다(호칭·외관으로만 판단) → §2 게이트로 결측 처리.
- 구현: X1 과 같은 요부관찰 정규화(회사 형태·부가어·영문 기능어·`extra_generic` 제거, 발음 변환 없음) → 토큰을 공백으로 이어 다국어 문장 임베딩 → 코사인 → §4 재보정. 정규화 텍스트가 같으면 임베딩 없이 1.0. 임베딩은 이름별 `lru_cache`(4,096), 모델은 프로세스에 한 번만 로드(첫 호출 때).

## 2. 관념 게이트 `has_meaning`

- 정규화 토큰 중 **하나라도 실제 단어**이면 True. 실제 단어 = wordfreq 빈도표에서 토큰을 **통째로** 찾은 zipf(log10 빈도 + 9)가 임계값 이상 — 한국어 `ZIPF_MIN_KO` 2.5, 영어 `ZIPF_MIN_EN` 3.0(명세 초기값). 숫자·한자·기호·자모만은 False.
- 통째로 찾는 이유(2026-09-30 실측): `wordfreq.zipf_frequency` 는 한국어를 MeCab 으로 형태소 분리해 합산하므로 조어도 높게 나온다 — 스타벅스 3.94(스타+벅스), 엘쏘 4.45(엘+쏘), 바른치과 3.90. 표제어 직접 조회(`get_frequency_dict`)면 스타벅스·엘쏘·XSR·커피빈은 0.0 이고, 단일 단어의 값은 `zipf_frequency` 와 같다. MeCab(cjk extra) 의존성도 필요 없다.
- 빈도표 범위: 한국어는 small 목록(29,988어, 최소 zipf 3.01)이라 2.5 는 사실상 "표에 있는가"이고, 영어는 large 목록(321,180어, 최소 1.01)이라 3.0(백만 단어당 1회)이 실제로 걸러 낸다.
- DB 실측: 상표명이 있는 947건 중 True **577건(61%)**. MeCab 합산 방식이면 731건.
- **사전어 브랜드는 관념 비교 대상**(v1.1 결정): 카카오(cacao, zipf 4.25)·애플(4.42)처럼 사전에 있는 브랜드명은 실제 단어이므로 True 가 맞다. 영어도 starbucks 3.77·samsung 4.12·hyundai 3.44 가 통과한다. 브랜드/단어 구분은 게이트가 아니라 통합 모델과 정답 데이터의 몫이다.
- **붙여쓴 합성어 폴백**(v1.1, 결정표의 V2b + 4.0 채택): 한국어 토큰이 표제어가 아니면 모든 분할점에서 두 부분으로 나눠 **양쪽 2음절 이상 & 각 부분 zipf ≥ `COMPOUND_MIN_ZIPF`(4.0)** 이면 단어로 본다. 왼쪽이 관형형이면(표제어가 아니고 마지막 음절이 은·는·한·운·인·된·을·할 이거나 받침 ㄴ·ㄹ) 어미를 뗀 어간(검은 → 검, 행복한 → 행복, 푸른 → 푸르)으로 조회하고, 그런 관형형 뒤에는 1음절 명사도 허용한다(행복한집 → 행복한 + 집). 임베딩 텍스트는 띄어 쓴 형태("검은 고양이")를 쓴다. 여러 분할이 가능하면 두 부분 zipf 의 최솟값이 큰 쪽, 세 부분 이상은 나누지 않는다.
  - 실측(2026-09-30): 검은고양이 True(검은 → 어간 검 4.94 · 고양이 4.84, 점수 검은고양이/BLACK CAT 0.984), 푸른하늘 True(푸른 4.37 · 하늘 5.00), 행복한집 True(행복한 → 행복 5.31 · 집 5.81), 서울우유 True; 스타벅스 False(벅스 3.97 < 4.0), 엘쏘 False(1음절), 카카오프렌즈 False(프렌즈 3.88), 트로피카나 False. DB 고유 이름 653건 중 통과 **414 → 425(+11)**(947건 기준 577 → 595). 새로 통과한 11건: 자연가치, 행복충전, (주)부동산포스, 배민 우리동네, 소중한너, 명인명품, 아이조이, 세대공감 소통리더십, 고속회관, 행복맛집 상국이네, 쿠팡은 로켓배송! — 모두 뜻이 읽히는 합성어다.
  - **채택 근거(2026-09-30 확정)**: 명세 초안(V0 3.5 — 표제어만, 양쪽 2음절)은 검은고양이·행복한집을 False 로, 스타벅스를 True 로 판정했다. 관형형(검은·행복한)은 MeCab 기반 목록에 표제어가 없고(어간 검 4.94·행복 5.31 은 있음), 집은 1음절, 벅스는 3.97 이기 때문이다. 아래 결정표에서 여섯 기대(검은고양이·푸른하늘·행복한집 True, 스타벅스·엘쏘 False, 카카오프렌즈는 보수적으로 False)를 전부 충족하는 것은 V2b + 4.0 뿐이고, 새로 통과하는 11건이 모두 유의미한 합성어라 채택했다. 카카오프렌즈(프렌즈 3.88)·트로피카나(트로피+카나, 3.5 에서만 통과)는 보수적으로 제외된다. V3(MeCab 합산)는 의존성이 늘고 조어(스타벅스)도 통과시켜 제외했다.
  - 결정표(같은 6개 이름, DB 고유 653건 통과 수·신규):

## 4. 재보정(c₀)과 임계값

- c₀ = DB 상표명 중 has_meaning True 577건의 정규화 텍스트(고유 410개)에서 무작위 200쌍(seed 0)의 코사인 평균 → `BASELINES`(MiniLM 0.3313, LaBSE 0.2049, e5 0.7716). c₀ 이하는 0(무관), 1 은 동일. 표에 없는 모델은 c₀ 0.0(원 코사인) + 경고 로그.
- 테스트 단언값(v1.1 결정): 유사 ≥ 0.6·비유사 ≤ 0.35. 선정 모델의 점수 분포(유사 최소 사과/APPLE 0.617, 비유사 최대 왕/사과 0.318)에 맞춘 **단언값이지 서비스 임계값이 아니다**. 명세 초기값 0.7/0.3 은 유사 9/11·비유사 7/8 만 통과했다. 상위개념(과일/사과 0.576, 동물/고양이 0.145)은 0.6 아래다.

## 5. 한계 (v1)

- **상위개념**: 과일/사과 0.576, 동물/고양이 0.145 — 유사 쌍보다는 낮지만 일정하지 않다.
- **연상·동의어**: 왕/QUEEN 0.516, 사랑/LOVER 0.681, 커피/카페 0.611 처럼 연상은 과대평가하고, 왕/임금 0.063 처럼 한국어 동의어는 놓친다(MiniLM 의 한국어 어휘 한계).
- **다의어**: 사과 = apple/apology → 사과/APPLE 0.617, 사과/APOLOGY 0.174. 문맥이 없어 뜻을 고를 수 없다.
- **게이트**: 사전에 있는 브랜드(카카오, STARBUCKS)는 관념이 있는 단어로 통과한다(v1.1 결정). 부분이 zipf 4.0 미만인 합성어(카카오프렌즈: 프렌즈 3.88)와 신조어·표제어 없는 낱말(자연주의)은 결측이고, 두 표제어로 우연히 나뉘는 조어는 4.0 이상이면 통과할 수 있다(아이조이 = 아이+조이). 관형형 어미 목록(은·는·한·운·인·된·을·할, 받침 ㄴ·ㄹ)은 초안이라 다른 활용형(검던)은 못 잡는다. 회사 형태만 남은 이름(주식회사)은 제거 전 토큰으로 폴백해 True 다.
- **환경**: 모델을 내려받지 못하면 첫 계산에서 `RuntimeError`(입력 오류가 아니라 환경 오류). 로드 8.6초(캐시), 최대 RSS 약 1.2GB — 백엔드에 붙일 때 기동 비용이다.
- 점수는 교정 전 원점수다. 로지스틱 회귀 학습 전 정답 데이터(다빈-1)로 게이트 임계값·c₀·모델을 재검토한다.

## 6. 성능 실측 (2026-09-30, `x3_benchmark.py --perf`)

- 모델 로드 8.6s(캐시 후), 최대 RSS 53 → 1,196MB. DB 이름 947건(고유 텍스트 646) 배치 임베딩 0.5s(0.8ms/건), has_meaning 577건 0.3s, 최대 RSS 1,267MB.
- has_meaning 이름 1,000쌍 `semantic_similarity`: cold 2.16s(이름별 1건씩 임베딩해 캐시 391건 채움) → warm 15ms. DB 전수 사전 계산이 가능한 수준(X1 1,000쌍 0.21s 와 비교해 임베딩 비용은 있으나 배치로 상쇄).

## 7. 인터페이스

```python
import sys; sys.path.insert(0, "ml")   # 프로젝트 루트에서
from src.axes.x3_semantic import has_meaning, semantic_similarity

has_meaning("스타벅스")                                                  # False → X3 결측
semantic_similarity("왕", "KING")                                       # 0.807
semantic_similarity("스타벅스", "커피빈")                                 # 0.0 (결측이지 비유사가 아님)
semantic_similarity("카페 봄", "봄", extra_generic=frozenset({"카페"}))  # 1.0 (정규화 텍스트 동일)
```

- `extra_generic` 은 X1 과 같은 의미·같은 매칭(단일 토큰 항목은 영문 읽기와도 대조). 양쪽에 같은 집합을 넘긴다.
- 환경변수: `MARKLENS_X3_MODEL`(sentence-transformers 모델 이름; `BASELINES` 에 없으면 c₀ 0), `MARKLENS_FAKE_ML`(가짜 임베더 — 문자 3-gram 해시, 점수 의미 없음, 불변식만 검증).
- 통합 시 주의: `has_meaning` False 는 결측으로 두고 다른 축만 쓴다. 서비스 연결 시 기동 때 DB 이름 임베딩을 배치로 사전 계산(0.5s)한다.
