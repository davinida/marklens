## 2. 점수 구성 (토큰 하나, `Distinctiveness.judge`)

1. 유명 브랜드(브랜드표 101개의 로마자·한글 + `shared/famous_brands.txt` 출원인명의 상호 핵심 토큰 + 브랜드 토큰 줄(2026-10-11 갤럭시·GALAXY·오리온·ORION — 주지·저명, 2017후2697 요부 판단의 첫 요소), 합계 235) → **1.0 고정**(주지·저명 근사).
2. 33조 1항 유형(1·3·4·5·6호)에 하나라도 해당 → **0.0**(사유에 해당 호를 모두 적는다).
2-1. 사람 검토 제외(`weak_token_overrides.json` 의 `excluded`, 2026-10-11 현재 crown·crystal·galaxy·iris·orion·secret·teddy) → 아래 3.의 통계 약화를 건너뛰고 **1.0**(3호 상대어의 상품 미상 상한 0.5 는 적용). v0.1 까지는 overrides 가 법정 사유보다 앞섰으나 v0.2 부터 법정 사유가 먼저다(crystal 은 14·21류 쌍에서 0, 그 밖의 류에서 1.0).
3. 그 외 → **본질적 식별력 × 다수 등록 계수**
   - 본질적 식별력 = 1 − 0.5 × clamp((zipf − 3.0) / (5.5 − 3.0), 0, 1). wordfreq 표제어 빈도 zipf 3.0 이하(희귀어·조어·숫자)는 1, 5.5 이상(아주 흔한 일반어)은 0.5 하한. X3 의 `token_zipf` 를 재사용한다.
   - 다수 등록 계수 = 1 − min(1, A/θ_A) × min(1, N/θ_N). 서로 다른 출원인 수 A 와 등장 수 N 이 **둘 다** 커야 0 에 가깝다(한 출원인이 50개를 가진 하우스마크는 약해지지 않는다). A·N 은 `token_stats.json`(N ≥ 2 인 7,118 토큰)에서 읽고 없으면 계수 1.
4. 요부 후보 = 점수 ≥ θ 인 토큰(`salient_tokens`). 약한 토큰 = 점수 < θ(`weak_tokens`). 요부 후보가 없으면 `has_distinctive_part` False.

예(전역 판정, 2026-10-09 집계): dream 0.0(일반어 4.9 × A 44·N 48), gate 0.65(일반어 4.5, A 4·N 4 — 약하지 않음), series 0.23, 닥터 0.03, 카페 0.16, 커피 0.0(1호 전역), 서울 0.0(4호), 김가네 0.0(5호), dr 0.0(6호), 삼성·스타벅스 1.0(유명 브랜드), 조어 1.0.

### 축 연결(`pair_generic`, `ml/scripts/pairs_features.py`)

- 쌍의 유사군 = `goods_codes_this ∪ goods_codes_prior`(없으면 전역). 두 이름 각각 `has_distinctive_part` 이면 그 이름의 약한 토큰을 모아 `extra_generic` 으로 X1·X2 철자·X3 에 넘긴다 → `x1_d`·`x2_text_d`·`x3_d`. 요부가 없는 이름은 토큰을 넘기지 않는다(2000후2453).
- **결합 규칙 v0.2 → v0.4**(`combined_weak_run`, 2026-10-11 → 2026-11-23): 약한 토큰 2개 이상이 두 이름 모두에서 붙어 있는 같은 구간(연속 공통 구간, 여럿이면 모두)이면 그 토큰들은 결합된 요부 후보로 보아 넘기지 않는다(2015후1690 결합상태). Cool Touch / 쿨터치 COOL TOUCH → (cool, touch) 결합이라 `extra_generic` 비어 전체 대비 1.0 유지, Q-FIRE / Q-FIRE 500MP → (q, fire) 결합·mp 만 넘김. 공통 약한 토큰이 하나뿐이면(Zorbix Gate / Hello Gate 의 gate) 그대로 넘기고, 순서가 다르면(Touch Cool / Cool Touch) 적용하지 않는다. 어느 한쪽에서라도 사이에 다른 낱말(약하든 아니든)이 끼면 묶지 않는다 — 맛있는 커피 전문점 / 맛있는 만두 전문점 장수손만두 1976 의 맛있는·전문점(v0.4, 견고성 점검 R-P0-2 — §4-3). v0.2–v0.3(규칙 1)은 양쪽 약한 토큰열(이름 순서)의 가장 긴 공통 부분열이라 사이 낱말을 보지 않았다 — `combined_weak_run(…, version=1)`·`pair_generic(…, weak_run_version=1)` 로 남긴다(지금 계수가 학습된 특징의 규칙, `pairs_features.py` 의 `WEAK_RUN_VERSION`). 서비스 엔진은 계수 JSON 의 `weak_run.version` 을 쓴다(통합 모델 v1.4.3 부터 2, 없으면 1).
- **결합 규칙 v0.3**(`combined_single_match`, 2026-10-11): 한쪽 이름의 토큰 하나(붙여쓴 결합어)가 다른 쪽의 연속 토큰 2개 이상(약한 토큰 포함)을 이어 붙인 것과 같으면 그 토큰열의 약한 토큰(결합어가 약하면 그것도)을 넘기지 않는다. "같다"는 ① 정규화 철자 동일(SLIMLINE = slim+line, 혹달린신발 = 혹+달린+신발) ② 철자 편집거리 유사도 ≥ `COMBINED_SIMILARITY` 0.9(자모 단위, 토큰으로 다시 나누지 않음) ③ 토큰별 X1 읽기를 이어 붙인 호칭이 결합어의 읽기와 동일(슬림라인 = 슬림+라인, 퀵패스 = QUICKPATH 의 읽기) ④ 읽기 유사도 ≥ 0.9. ROYALEBEE / ROYAL BEE 는 0.889 로 임계 미달이고 쿨터치 / COOL TOUCH 는 X1 이 touch 를 ‘타우치’로 읽어 미달이지만, 두 쌍 모두 토큰이 전부 약해 v0 규칙(2000후2453)으로 이미 전체 대비다. 어순이 바뀐 에어부산 / BUSAN AIR 는 적용하지 않는다.
- X1 의 "제거 전 전체 결합" 후보는 X1 이 그대로 유지한다(전체관찰). X2 철자는 제거 후 토큰만 비교하므로 효과가 더 크다.

## 6. 한계(v0)

- **3호는 사람 승인 목록(449항목)에 한정** — 상대어 378 은 일괄 승인이라 분류 초안의 류 판정이 그대로 쓰인다. 도안화가 글자를 압도하는 경우(X2 유형 판정 과제), 거래실정(실제 사용례), 암시·강조 판단의 주관성은 사람 승인에 기대며, 상품 미상 쌍(163)에서는 상대어가 0.5 상한에 머물러 제거되지 않는다(§3-3).

  결과를 `ml/src/name_words.py` 의 `describe` 가 응답 꼴로 옮긴다 — 낱말(엔진의 토큰 그대로), 식별력 여부(`TokenJudgement.is_weak` 의 반대 —
  점수 < θ 0.5 면 없음, 요부 후보를 고를 때와 같은 기준), 식별력이 없을 때의 화면용 분류, 사유 원문.
- 식별력 판정으로 뺀 낱말과 상품 접미어로 뗀 낱말이 모두 담긴다 — 접미어 분리가 판정보다 먼저라 `블루커피` 는 `블루`·`커피` 두 낱말로
  판정된다. 유명 브랜드 예외(1.0 고정)는 엔진과 같게 식별력 있음이다.
- 함께 싣는 것: 모든 낱말이 낱말 단위로 식별력 없는 말인지(`all`)·일부만인지(`some`)·없는지(`none`). 낱말은 여섯 개까지만 싣고 나머지는
  수만 싣는다(나머지 가운데 식별력 없는 낱말 수도).
- 이름이 없는 질의에는 싣지 않는다. 이 기능 때문에 질의 이름을 로그에 새로 남기지 않는다(정리 중 예외가 나면 예외 종류만).

### 9-2. 사유 코드와 화면용 분류

엔진이 내는 사유 코드(`TokenJudgement.reasons` 한 항목의 머리 — §2 의 점수 규칙이 붙인다)는 모두 열다섯 갈래다. 넓은 낱말 집합
(약한 토큰 사전·3호 사전·지명·성·유명 토큰·고시 명칭 등 5,156낱말) × (상품 없음 + 업종 세트 25개)의 판정 134,056건에서 다른 코드는 나오지
않았고, 식별력 없는(점수 < 0.5) 낱말에 붙는 코드는 아래 표의 여섯 묶음뿐이었다.

| 엔진의 사유 코드 | 점수 | 화면용 분류 | 분류 문구 |
|---|---|---|---|
| `1호 보통명칭` · `1호 보통명칭(전역)` | 0 | 상품 이름 | 파는 상품이나 서비스의 이름 그 자체예요 |
| `3호 기술적 표장(절대):{종류}` · `3호 기술적 표장:{종류}(류 …)` | 0 | 성질·품질 | 맛·품질·재료·쓰임새 같은 성질을 설명하는 말이에요 |
| `4호 지명` | 0 | 지역 이름 | 널리 알려진 지역 이름이에요 |
| `5호 흔한 성` | 0 | 흔한 성·이름 | 흔한 성이나 흔히 쓰는 이름이에요 |
| `6호 간단 표장` | 0 | 짧고 흔한 글자 | 너무 짧거나 흔한 글자·숫자예요 |
| `다수 등록(A=…, N=…)` · `일반어(zipf …)` — 점수가 0.5 미만일 때 | 0–0.5 | 흔히 쓰는 말 | 여러 상표에 흔히 쓰이는 말이에요 |
| `빈 토큰`(이름에서 나온 낱말에는 붙지 않는다)·앞으로 생길 코드 | 0 | 그 밖 | 식별력이 약한 말이에요 |
| `유명 브랜드` · `조어` · `사람 검토 제외(…)` | 1.0 | (식별력 있음 — 분류 없음) | |
| `3호 기술적 표장(상품 미상):{종류}` · `3호 기술적 표장(류 미지정):{종류}` | 0.5 로 누름 | (식별력 있음 — 0.5 는 θ 이상이라 약한 낱말에 붙지 않는다) | |

- **"그 밖"으로 간 코드는 없다.** `빈 토큰` 만 대응해 두었고 실제 응답 1,017건(§9-4)의 식별력 없는 낱말 가운데 "그 밖"은 0이다.
- 3호의 종류(품질·용도·원재료·형상·효능·사용방법·시기·생산방법 — 식별력 없는 낱말에 붙은 것)는 모두 성질표시라 한 분류로 묶었다. 산지는
  사전에 두 낱말(`american`·`korean`)뿐이고 류 미지정이라 점수를 누르기만 한다.
- **사유가 여럿인 낱말**은 표의 위에서부터 먼저 맞는 분류를 쓴다(1호 → 3호 → 4호 → 5호 → 6호 → 통계). 엔진의 사유 나열은 3호가 앞이지만
  (카페 업종의 `커피` = `3호 기술적 표장:원재료(류 30,35,43)·1호 보통명칭`), 그 업종의 상품 이름인 낱말은 "상품 이름"이라고 말하는 쪽이
  알아듣기 쉽고 큰 안내의 예시("예: '○○ 커피'처럼요.")도 그 낱말로 만든다. 함께 나온 조합: 3호 + 1호, 1호 + 4호(`양산`·`경기`),
  5호 + 6호(한 글자 성), 3호 + 6호(`젤`·`톱`), 일반어 + 다수 등록.
- 상품 접미어는 사유 코드가 아니다(판정 전의 낱말 나누기). 떼어 낸 낱말은 그 업종의 고시 명칭이면 1호(상품 이름), 다른 업종이면 통계나
  3호로 분류된다(의류 세트의 `블루커피` → `커피` 는 `3호 기술적 표장:원재료(류 35)`).

### 9-3. 질의의 업종만으로 본 판정과 쌍별 판정

엔진에는 "질의 이름의 판정"이 따로 없었다 — 요부는 **쌍마다** 질의 업종 ∪ 후보 업종으로 정한다(1호·3호가 상품에 상대적이라, §2 축 연결).
응답에 실은 것은 같은 함수를 질의의 업종만으로 부른 값이고, 둘의 관계를 실제 엔진으로 쟀다(§9-4 의 질의, 풀 전체의 이름 있는 후보와의 쌍).

| | 업종을 고른 질의(514) | 업종이 없는 질의(503) |
|---|---|---|
| 응답 = 식별력 판정 함수가 질의의 이름·업종에 내는 값 | 514 | 393 — 나머지 110질의는 아래 "업종이 없는 질의" |
| 쌍(질의 × 풀의 이름 있는 후보) | 29,967 | 20,537 |
| 응답이 식별력 없다고 한 낱말을 엔진이 요부 후보로 쓴 쌍 | **0** | **0** |
| 쌍의 판정 = 응답의 판정 | 29,518(98.5%) | 17,888(87.1%) |
| 후보의 업종 때문에 그 쌍에서만 낱말이 더 약해진 쌍 | 449(1.5%) | 2,649(12.9%) |

- **업종을 고른 질의**: 쌍의 업종이 질의의 업종을 품으므로 응답이 식별력 없다고 한 낱말은 어느 쌍에서도 약한 채로 남는다(요부 후보가 된
  쌍 0). 남는 차이는 한 방향뿐이다 — 응답은 식별력 있다고 한 낱말이 후보의 업종에서는 1호·3호라 그 쌍에서만 빠진다.
- **업종이 없는 질의**: 판정 함수는 업종을 모르면 "어느 업종의 상품 이름"(`1호 보통명칭(전역)`)도 약하다고 보는데, 엔진은 쌍마다 후보의
  업종으로 판정해 그 업종과 무관한 후보에는 그 낱말을 요부로 쓴다. 그대로 실으면 응답이 "식별력 없는 말"이라고 한 낱말을 엔진이 요부로 쓴
  쌍이 생기고(미리 잰 값: 설명적 이름 200의 풀 쌍 18.6%), `큰 나무` 가 큰 안내("나무 — 파는 상품이나 서비스의 이름 그 자체예요"),
  `징검다리` 의 `다리` 가 상품 이름이 된다. 그래서 **그 판정이 식별력 없다고 한 낱말이라도 엔진이 어느 후보(풀 전체)와 견줄 때 요부 후보로
  썼으면 그 쌍의 판정으로 바꿔 식별력 있음으로 싣는다.** 503질의 중 110질의에서 그랬고 그 낱말의 사유는 모두 `1호 보통명칭(전역)` 이었다.
  업종과 무관한 사유(지명·흔한 성·짧은 글자·절대적 기술 표장·통계)는 그대로 실린다. 업종이 없으면 안내가 보수적이 된다는 뜻이다.

  배너(약함)만) · `블루커피` + 카페 → 작은 안내("'커피'는 누구나 쓰는 말이라 빼고 비교했어요.") · `파리바게트` + 빵집 → 엔진이 접미어
  `바게트`(고시 명칭)를 떼어 `파리`(지역 이름)·`바게트`(상품 이름) 둘 다 식별력 없는 말이지만, 배너가 이름의 강한 일치라 **유명 상표
  배너(강함)만**(설명적 이름 안내도 전체 등급 옆 한 줄도 없음 — §9-5).

### 9-5. 화면이 안내를 고르는 규칙과 그 문장이 사실인지

화면(`frontend/lib/descriptiveNotice.ts`, 계약 v2 §4-7)은 응답의 `name_words` 와 보이는 후보, 그리고 위의 유명 상표 배너로 안내를 고른다.

- **유명 상표 배너가 이름 쪽의 강한 일치로 뜨면 안내 없음**: 배너가 그리는 일치 가운데 강함이고 근거가 로고가 아닌 것(이름·이미지 속
  글자)이 있으면 큰 안내·작은 안내·"이름 전체를 견준 결과" 한 줄을 모두 그리지 않는다. 이름이 널리 알려진 상표와 같거나 거의 같다고 알리는
  자리에서 그 이름을 "누구나 쓰는 말"이라고 함께 말하지 않기 위해서다 — `파리바게트` + 빵집(엔진이 `파리`·`바게트` 로 나눔)과 `김가네` +
  분식이 그 경우다. 약한 일치의 배너, 로고로만 강하게 일치한 배너, 설명적 사용 안내에서는 아래 그대로다. 응답의 `name_words` 는 그대로
  실린다(화면만 그리지 않는다).
- **큰 안내**("이 이름은 상표로 등록받기 어려울 수 있어요" — "'{이름}'은(는) 모두 상품을 설명하거나 누구나 쓰는 말이에요."): 모든 낱말이
  식별력 없는 말이고, 그 가운데 **"흔히 쓰는 말"이 아닌 분류**(상품 이름·성질·품질·지역 이름·흔한 성·이름·짧고 흔한 글자)의 낱말이 하나
  이상 있고, 유명 상표 배너(강함·약함)가 없을 때. "흔히 쓰는 말"은 심판 목록 표본의 통계(§2 다수 등록·일반어)라 `fox`·`books`·`garden` 같은
  흔한 낱말만으로 된 지어낸 이름까지 큰 안내가 뜨던 것을 막는다(대조군 이름+업종 5 → 2, 설명적 이름은 200 → 182).
- **작은 안내 — 모두**("'{이름}'은(는) 모두 누구나 쓰는 말이에요." + "자세히"): 모든 낱말이 식별력 없는 말인데 "흔히 쓰는 말"뿐이거나,
  유명 상표 배너(약한 일치, 또는 로고로만 강한 일치)가 있을 때.
- **작은 안내 — 일부**("'{낱말들}'은(는) 누구나 쓰는 말이라 빼고 비교했어요." + "왜요?"): 일부 낱말만 식별력 없는 말이고, **"빼고
  비교했어요"가 보이는 후보 모두에서 사실일 때만** — 이름을 견준 후보(상표명이 있는 후보)마다 그 낱말들이 뺀 낱말(`salient.removed`, 질의
  쪽)에 들어 있어야 한다. 실린 낱말은 어느 쌍에서도 요부 후보가 아니지만(§9-3), 결합 규칙이 그 낱말을 요부로 되돌린 쌍(§4-1·§4-2)이나 후보의
  업종 때문에 그 쌍에서는 질의에 요부가 없어 전체로 견준 쌍에서는 빼지 않는다. 사실이 아니면 이 안내를 그리지 않는다 — 일부만 식별력 없는
  질의 가운데 보이는 것은 대조군 이름+업종 94/102(92.2%)·이름만 87/95(91.6%), 업종이 없는 설명적 이름은 0/72(한 낱말 — 전역 보통명칭 — 만
  요부로 쓰인 이름이라, 그 낱말이 약해지는 후보와는 전체로 견준다).
- **"이름 전체를 견준 결과"**(모든 낱말이 식별력 없는 말일 때 전체 등급 옆 한 줄): 엔진은 요부가 없는 이름의 낱말을 **질의 쪽 판정으로는
  빼지 않는다**(§2 축 연결 — 전체로 대비, 2000후2453). 다만 후보에 요부가 있어 그쪽의 약한 낱말을 뺄 때 그 낱말이 질의에도 있으면 양쪽에서
  함께 빠진다(제외 토큰은 양쪽에 공통으로 적용 — `맛있는 커피 전문점` ↔ `맛있는 건강 본죽` 에서 `맛있는`). 설명적 이름 200·이름+업종의 상위
  5 후보 1,000쌍 중 23쌍(2.3%), 풀 전체로는 3.9% 가 그랬고, 그런 후보가 상위 5 에 하나라도 있는 질의는 15(7.5%)다. 그래서 이 줄은 **보이는
  후보 가운데 질의의 낱말이 빠진 것이 하나도 없을 때만** 그린다(185/200 에서 보인다). 기대 예시 `맛있는 커피 전문점` + 카페는 보이지 않는
  쪽이다. X1 은 이때도 전체 결합음과 함께 낱말 하나하나를 따로 견준다(§2·X1 설계 — 통합 모델이 요부 없음 항으로 그 몫을 줄인다).
- 쌍마다의 사실은 후보 카드의 문장(계약 §4-2)이 그대로 말한다.

### 9-6. 한계

- **업종이 없으면 보수적이다** — 전역 보통명칭만으로는 설명하는 말로 보지 않는다(§9-3). 설명적 이름 표본에서 모든 낱말이 식별력 없는 말인
  이름이 이름+업종 200 에서 이름만 123 으로 줄고(큰 안내는 182 → 39), 일부만인 72 는 "빼고 비교했어요"가 사실이 아니어서 안내가 없다.
- **1호는 류 단위라 넓다** — 유사군 코드가 걸친 류의 고시 명칭이면 1호다(§2). 카페 세트에서 `나무` 가 "상품 이름"이 된다(`큰 나무` + 카페 →
  큰 안내).
- **35류가 든 업종** — 3호 사전의 낱말이 류만 맞으면 설명하는 말이다. 의류 세트에서 `커피` 가 성질·품질(류 35)로 나온다.
- **통계로 약한 흔한 낱말** — `fox`·`books`·`garden`·`행복한` 같은 낱말이 "여러 상표에 흔히 쓰이는 말"로 나와, 지어낸 이름의 절반 가까이에
  작은 안내가 뜬다(큰 안내는 이런 낱말만으로는 뜨지 않게 했다 — §9-5). A·N 이 심판 목록 표본이라(§6) 한글 `블루`(A 4)는 식별력 있음, 영문 `blue`(A 53)는 없음처럼 고르지 않다.
- **목록에 없는 낱말** — 회사 형태·부가어·영문 기능어(`주식회사`·`코리아`·`the`)는 축 함수가 판정 전에 버려 낱말 목록에 없고(`주식회사 커피
  코리아` → `커피` 하나), 한자·기호 낱말도 없다. 영문은 소문자로 보이고, 영문 고시 명칭은 대조하지 않아 `coffee` 는 상품 이름이 아니라
  성질·품질(3호)이다.
- **`식당`·`전문점` 같은 업종 말** — 고시 명칭이 `식당업`·`커피전문점업` 꼴이라 `식당` 은 1호가 아니다(`서울 식당` 은 작은 안내). 유명 상표
  판정(통합 모델 설계 §7-14-9)은 업종 낱말 사전을 따로 두지만 여기서는 엔진의 식별력 판정만 쓴다.
- **접미어로 나뉜 이름** — `파리바게트` 는 엔진이 `파리`·`바게트` 로 나눠 둘 다 식별력 없는 말이 된다(응답의 `name_words` 는 `all`).
  유명 상표 배너가 이름의 강한 일치로 떠서 화면은 안내를 그리지 않지만(§9-5), 유명 상표 등록부에 없는 이름이 이렇게 나뉘면 안내가 뜬다.
- 여섯 개를 넘는 낱말은 수만 실려 화면이 "외 N개"로만 말한다.
