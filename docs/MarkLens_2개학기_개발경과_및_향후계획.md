## 1. 한 페이지 요약

### 핵심 설명

MarkLens는 사용자가 업로드한 로고와 기존 등록상표 이미지를 비교해 시각적으로 가까운
선행 후보를 보여 주는 시스템입니다. 상표명 완전일치 결과와 권리 정보를 함께 제공해,
사용자가 후보를 직접 확인할 수 있도록 구성했습니다.

> **1학기에는 이미지 유사 검색이 가능한 ML·API 프로토타입을 만들었고, 이후 2학기
> 상당분의 후속 개발로 실제 KIPRIS API, 웹 화면, 데이터 수집·정합성, 보안, 평가
> 체계를 갖춘 로컬 연구 베타까지 고도화했습니다.**

## 2. 문서 기준과 주차 해석

1학기 기준선은 `main@a4e3f11`이며 17개 커밋으로 구성됩니다. 후속 고도화의 확정
이력은 `main..develop`의 32개 커밋이고, 현재 기준 `develop@f95aaa1` 위에 통합 작업이
추가되어 있습니다.

아래 주차표는 Git 이력, 구현 의존 관계와 실행 산출물을 **15주 교과 진행 순서로
구성한 개발 기록**입니다. `main..develop`의 32개 커밋에는 merge commit 2개가
포함되며, 현재 작업 트리의 통합 변경은 아직 commit 전 상태입니다. 세부 commit과
artifact 증거는 10절에서 관리합니다.

데이터 계보도 구분합니다. `main` README에는 100건 표본이 기록돼 있지만 `ml/data/`는
Git에서 제외되어 해당 branch만으로 실데이터를 재현할 수 없습니다. 이후 BBQ 업종
파일럿 5건을 추가해 105건이 되었고, 신규 895건을 격리 수집·승격해 현재 1,000건이
되었습니다.

산출물 출처는 다음과 같습니다. 각 표의 결과 칸은 당시 문서·테스트·실행 기록의 수준을
그대로 적으며, 커밋 존재 자체를 운영 검증 완료로 해석하지 않습니다.

- `Git 확정`: 산출물이 현재 브랜치 이력에 존재한다는 뜻이며 운영 검증 완료를 뜻하지 않음
- `현재 검증`: 로컬 통합 작업본에서 명시된 테스트·실행을 확인했지만 아직 미커밋인 작업
- `기준선 확보`: 코드·artifact·실행 기록으로 구현 범위와 미완료 경계를 확인한 항목
- `학기 검증 예정`: 해당 주차에 수업 환경에서 실행·분석·시연할 예정인 활동
- `계획`: 앞으로 수행할 작업

### 후속 고도화 현재 판단

2학기 상당분으로 재구성한 후속 고도화의 핵심은 단순히 데이터를 늘린 것이 아닙니다.
**월간 API 예산 안에서
중단·재시도·격리·감사·원자 승격이 가능한 데이터 파이프라인을 만들고, 그 결과를
사용자가 웹에서 근거와 함께 확인할 수 있게 한 것**이 주요 성과입니다.

현재 시스템 흐름은 다음과 같습니다.

```text
[사용자 이미지 검색]
브라우저 -> Next.js 서버 중계(BFF) -> FastAPI -> 로컬 OpenCLIP·FAISS 인덱스

[사용자 상표명 확인]
브라우저 -> Next.js 서버 중계(BFF) -> FastAPI -> KIPRIS Plus API

[관리자 데이터 수집]
KIPRIS Plus API -> 격리 저장 -> 감사·승격 -> 로컬 파일 인덱스(현재 실행 경로)
                                      -> PostgreSQL 저장 경로(코드·migration 구현)
```

PostgreSQL 저장 계층과 migration은 구현되어 있지만, 현재 1,000건 확장과 runtime
검증은 `DATABASE_URL` 없이 파일 스테이징 모드로 수행했습니다.

## 5. 해결한 핵심 문제와 설계 결정

| 문제 | 적용한 해결책 | 현재 효과 |
|---|---|---|
| 높은 유사도인데 낮은 단계가 나오는 scoring 역전 | 절대 유사도 안전장치, 고정 scoring 후보 수, 불확실성 필드 | 표시 개수와 무관한 일관된 참고 상태 제공 |
| 브라우저에 backend key가 노출될 수 있음 | Next.js 동일 출처 서버 중계(BFF)와 서버 전용 key | 브라우저와 내부 API 경계 분리 |
| KIPRIS query에 key·상표명이 포함됨 | HTTPS 강제, URL 비노출 로그, 안전한 오류 변환 | key와 검색어의 로그 유출 위험 축소 |
| 수집 실패 후 메타·이미지·인덱스가 어긋남 | 원본 저장, checkpoint, 승인 데이터 목록(authoritative key), 작업 중 표시(dirty marker), 원자 승격 | 실패 시 배포를 막고 복구 가능한 상태 유지 |
| 동일 명칭 결과가 텍스트 한 줄로만 보임 | 후보 목록, 상태 분포, 로고·출원번호·권리자 클릭 상세 | 사용자가 중복 판단 근거를 직접 확인 |
| 모델·전처리·인덱스 세대가 섞일 수 있음 | manifest에 모델·전처리·해시·산출물 세대(generation) 기록 | startup과 평가 시 산출물 불일치 차단 |

후속 고도화에서는 실제 KIPRIS API와 Next.js 화면을 연결하고 PostgreSQL 저장 경로,
보안 경계, 자동 테스트를 구현했습니다. 현재 데이터 실행은 파일 모드입니다. 또한
수집 실패에도
복구할 수 있는 체크포인트·격리·원자 승격 파이프라인을 만들었습니다. 이
파이프라인으로 월 호출 안전 한도 안에서 권리·이미지·벡터를 각각 1,000건으로 맞췄고,
45개 Nice 상품류를 모두 포함했습니다.

현재 결과는 법적 판단 모델이 아니라 시각적 선행 후보 검색 연구 베타입니다. 11월에는
canonical image·안전한 SVG rasterization·vector·손글씨 강건성 실험을 수행하고,
12월에는 200쌍 사람 라벨링, 임계값 동결, frozen holdout 단회 평가와 운영 rehearsal을
진행합니다. 이 근거가 준비된 뒤에만 호칭·관념·상품 견련성 축을 검토합니다.
